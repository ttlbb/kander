# 任务建卡引导

## 创建与确认

仅对尚未选择执行方式的新 Bug 或功能需求提供引导. 已由 `start`、`resume` 或 `notify` 接续的任务及用户指定的现有卡, 继续执行原卡, 不重复询问或另建卡. 用户已明确选择走看板或直接执行时, 直接按所选流程执行, 不重复询问. 纯问答、只读排查、文档或配置微调、发布和合入不触发建卡引导.

当 `rules.task_groups=true` 且 `rules.git=true` 时, 呈现选项前先读 `KANDER-TASK-GROUP-RULES.md`「任务拆分与任务组」, 并在计划中说明这是一张卡还是一个任务组. 若为任务组, 还要列出成员卡标题、依赖顺序, 以及各组分支门禁通过后按依赖顺序合回 `develop` 的步骤. 卡片正文在确认后再写; 拆分与合回步骤随计划一起确认. 任务组关闭时只规划单卡, 不加载关闭模块.

完成分析与实施计划后一次性提供选项:

```text
- 确认计划并走看板 (建卡并启动)
- 确认计划并走看板 (建卡, 暂不启动)
- 确认计划, 不走看板, 在本会话直接做
- 调整计划
```

上述选项从 `1` 编号, 并使其成为该消息中唯一的编号问题, 序号就不会与其他问题重复.

- 选 `确认计划并走看板 (建卡并启动)` 同时授权计划、开发与看板流程, 包括计划中写明的合回步骤; 开工前和集成前都不再询问. 这覆盖独立单卡和已确认计划中点名的每个任务组.

  对 `rules.git=true` 的独立单卡, 该执行授权还覆盖集成到 `develop` 与清理, 条件见 `KANDER-GIT-RULES.md`「提交与 push」; 不再单独请求回并确认. 完成流程见 `KANDER-KANBAN-RULES.md`「执行与完成」.

  单卡依次执行 `kander new`、按已确认计划填写完整契约、按 `KANDER-KANBAN-RULES.md`「建卡后自审」完成自审与适用的独立审卡并修正、`kander pick <task-id>` (定义见 `KANDER-KANBAN-RULES.md`「命令契约」)、`kander start <task-id>`. 启动与跟踪责任按 `KANDER-KANBAN-RULES.md`「领取, 启动与协调」执行, 讨论 Agent 不再实现已委派的卡.

  对任务组, 以同样方式创建每张成员卡, 完成 `KANDER-TASK-GROUP-RULES.md`「任务拆分与任务组」中的组级检查, 然后按该文件编排. 已确认的计划就是编排计划; 它已带有其中点名的每个组的集成授权.

- 选 `确认计划并走看板 (建卡, 暂不启动)` 只授权计划与建卡. 创建卡片, 完成自审与适用的独立审卡, 让它们留在 `backlog/`; 不移入 `todo/` 也不启动. 之后启动需要用户再次指示; 该指示从 `kander pick` 起进入与第一个选项相同的流程 (`pick` 之后, 只有用户明确要求本 Agent 自己执行该卡时, 才按 `KANDER-KANBAN-RULES.md`「领取, 启动与协调」用 `kander move <task-id> working --owner <agent>` 代替 `kander start`), 并带有已确认计划的集成授权; 不再重复询问.
- 选 `确认计划, 不走看板, 在本会话直接做` 按项目规则直接实施, 不建卡.
- 选 `调整计划` 时修改计划, 尚不建卡或启动.
